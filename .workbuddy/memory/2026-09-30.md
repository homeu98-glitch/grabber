## Transaction Grabber：自動化流程重新定調（單一分頁模型）

用戶糾正咗之前嘅理解，最關鍵＝**單一 browser、單一分頁**（唔開第二個 tab，mfood 多 tab 會搶 session）。

協調流程（已畫流程圖確認）：
1. 登入 → 開單一頁面，預設留訂單頁。
2. 訂單頁每次循環冪等重設「訂單狀態＝全部」→ 代按查詢。
3. 按介面 timer 循環抓訂單；累加計時。
4. 每 30 分鐘（mfood + aomi 都一樣、不可設）觸發對帳。
5. 進入對帳＝**完全停止**訂單（busySettling 鎖 + 停頁面 timer + 跳過 rescan）。
6. 單一分頁 SPA 切去財務對帳頁（唔開新 tab）。
7. 抓一次對帳 → 推送 POS；**必須成功拿到數據**先切返訂單頁（否則重試）。
8. 切返訂單頁 → 恢復訂單循環、重置累加器 → 回到步驟 2。

實作必要改動：
- 移除 `grabPreparePagesForStart` 幫 mfood 開財務分頁嗰段（`grabEnsureTabForUrl`）。
- `grabSettlePlatform` 由「搵財務分頁」改為「導航單一分頁去財務 route，做完再導航返訂單 route」。
- 加 `busySettling` 鎖 + `GRAB_PAUSE_ORDERS` / `GRAB_RESUME_ORDERS` message。

## 🔴🔴 Element UI `popper-append-to-body` 陷阱：scope 修復反而搞壞正常路徑（2026-09-30 當晚）

用家截圖指出真機「訂單狀態」仲係「已完成」、冇變「全部」—— 我上輪加嘅 scoped 修復（`findVisibleOption("全部", closestByClass(box,"el-select"))`）方向錯。

**根因（已交叉確認）**：Element UI `el-select` 嘅 `popper-append-to-body` **預設＝`true`**（5 個來源確認，含官方文檔轉述）。即 dropdown `.el-select-dropdown__item` 會被 **teleport 去 `<body>`**，**唔喺** `.el-select` 子樹入面。
⇒ `closestByClass(box,"el-select")` 返到 `.el-select`（非 null）⇒ `findVisibleOption` 只喺 `.el-select` 子樹搵 ⇒ **搵到 0 個選項** ⇒ `pick()` 返 null ⇒ 重試 8 次都係 null ⇒ `ok:false` ⇒ 停留「已完成」。
mfood-bridge.js 第 919 行舊 comment 仲寫「預設 `popper-append-to-body=false`」—— **呢句本身就錯**，係我當時嘅錯誤假設。

**測試盲點（最重要嘅教訓）**：`test/range-bridge.test.cjs` 嘅 `makeOrderStatusSelect` fixture 舊設 `selectWrap.classList.contains: () => false` ＋ `input.closest: () => null`
⇒ 測試入面 `closestByClass` 永遠返 null ⇒ `findVisibleOption` 永遠用 `document` 全頁掃 ⇒ 過到測試，但 **scope 分支從未被執行過**（dead code）⇒ CI 全綠都唔代表 production scope 冇問題。

**修法（mfood-only）**：
1. `mfood-bridge.js` `pick()`：scoped 搵唔到就退返全頁掃 —— `findVisibleOption("全部", scope) || findVisibleOption("全部", null)`；第 919 行錯 comment 改正確。
2. `test/range-bridge.test.cjs` `makeOrderStatusSelect`：`selectWrap.classList.contains` 改返 `(c)=>c==="el-select"`（先可以行到 scoped 分支）；加 `querySelectorAll` 模擬 `popper-append-to-body` 兩種掛載（`optionsInBody:true`→`.el-select` 子樹搵唔到逼落 fallback；`false`→子樹內）。
3. 加兩條回歸：① `popper-append-to-body=true（dropdown 喺 <body>）都要設到「全部」`（舊 code 呢條 ok:false）；② `=false（dropdown 在 .el-select 子樹）scoped 分支 work`。

**驗證**：`mfood.test.cjs` **86/0**、`range-bridge.test.cjs` **109/0**（＋2 組回歸）全綠。隔離維持：只改 `mfood-bridge.js`＋`test/range-bridge.test.cjs`；`aomi-bridge.js`、`background.js`（含第 5 行 live key）完全冇動；冇留 `_` 前綴檔。

**📌 通用守則（記低，下次唔好再中）**：
- 凡係 `el-select` / 任何 teleport／portal 元件，**唔可以假設子節點喺某個祖先子樹入面**。要 scope 就一定要加「scope 搵唔到 → 退返 `document` 全頁掃」fallback；最後靠「撳完回讀欄位值」做唯一安全網。
- **測試 fixture 必須令 `closest` / `classList.contains` / `querySelectorAll` 真係返到預期值**，否則 scoped 分支係 dead code、CI 綠都冇意義。寫 scoped 查詢嘅同時一定要寫一條「dropdown 喺 body（預設）」嘅回歸，先鎖到真機行為。

## 🔴🔴 第二層：財務對帳 `store` 步「1620ms 內一個可見選項都冇」（2026-09-30 夜晚）

## 🔴🔴 第三層：商家下拉「人手撳一下就得，程式撳就永遠 0 個選項」（2026-09-30 深夜，用戶提供 DOM）

**用戶鐵證**（`@image#1` + 兩段 DOM）：「我只要幫這個步驟按了一下，打開了那個 drop down 就完成了整個對帳流程。」
同一個商家 input，撳之前 vs 撳之後**只有兩處分別**：
1. 外層 `.el-input` 多咗 **`is-focus`**
2. 箭頭 `.el-select__caret.el-icon-arrow-up` 多咗 **`is-reverse`**（箭頭由「上」轉「落」＝已展開）

而**一個 `.el-select-dropdown__item` 都冇出現**。

**根因（兩層）**：
- **① 合成 click 唔夠「真」**：`.click()` / `new MouseEvent("click")` 雖然 `bubbles:true`，但冇 `cancelable`、`button`/`detail` 唔齊、`isTrusted:false`。Element-UI/mfood 嘅下拉 handler 係食 **mousedown** 開 popper；合成 mousedown 過唔到 ⇒ 「開咗但空」。
  ⇒ 正解：行**真實 pointer 序列** `pointerdown → mousedown → mouseup → click`，全部 `bubbles + cancelable + composed + view + button:0 + buttons` + client 座標。
- **② 開咗之後選項係「懶載入」**：唔可以死等（舊 code 就係等 10×150ms 然後報「一個可見選項都冇」）。要**主動催**：
  - `keydown` **`ArrowDown`** ⇒ Element-UI `navigateOptions` 會真係 render 列表（實測最有效）
  - 必要時把 `.el-scrollbar__wrap` 嘅 `scrollTop` 推到目標選項
  - 仲有 0 個 ⇒ 用 `wrap` **重開一次**（toggle 可能被自己嘅 click 抵銷）

**判斷「開咗未」唔可以靠「有冇可見選項」**（真機就係開咗但 0 個）⇒ 用 `isPopperOpen(ctl)`：`.el-select__caret.is-reverse` 或外層 `.el-input.is-focus`。

**撳次序陷阱（實測中過）**：`.el-select` **外層**喺 Element-UI 係「click 即 toggle」，而 `input` 係「mousedown 開、click 唔 toggle」。如果「先撳 input 再撳 wrap」就會即刻被 toggle 返收埋 ⇒ **每次只派一次序列**：`hasTags || wrap 唔係 .el-input` ⇒ 撳 wrap；否則撳 input。

**新增程式**（`mfood-finance-bridge.js`，全部喺 `setStore` 內）：
- `realPointerPress(el)` — 派 pointer 序列，回 boolean
- `isPopperOpen(ctl)` — 睇 `is-reverse` / `is-focus`
- `dispatchKey(el, key, keyCode)` — `keydown`+`keyup`
- `scrollOptionIntoView(opts)` — 推 Element-UI 自家 scrollbar
- `tryOne(ctl, budget, isFirst)` — 開 → poll：`pickStoreOption` 中名就撳（都用 `realPointerPress`）→ `sleep(200)` **回讀瞄準目標欄位值**驗證；唔中就 `closePopper()` 試下一個候選。t%3 輪住用三招催選項。

**測試盲點（兩個新發現，好重要）**：
- **假 DOM 嘅 `makeEl` 只有 `click()`** ⇒ 就算 bridge 只寫 `el.click()` 都一定綠，完全測唔到「真機 click 開唔到」呢個重點。⇒ 假 DOM 補 `addEventListener`/`removeEventListener`/`dispatchEvent`（向上冒泡）、`PointerEvent`/`MouseEvent`/`KeyboardEvent` 類別（掛 `<body>` 亦要可以監聽）。
- **假 DOM 嘅「撳中」只掛 `opts.onClick`（只有 `.click()` 觸發）** ⇒ bridge 改用 `dispatchEvent` 之後，選項「搵到但撳唔到」，`clicked` 永遠 0 ⇒ 一堆「撳中 index N」**假紅**（實測中咗 11 條）；而 `storeSelectedText` 又可能靠 tags 路徑「撞啱」令 `ok:true` ⇒ 更難察覺。
  ⇒ **`clicked` 累加同平台 handler 都一定要掛 `addEventListener("click")`**，唔可以只靠 `opts.onClick`。

**另外修正兩個測試失真**：
- `[2]` 原本用 `dropdownOpen:false`（選項 0×0）。舊 bridge 只係**讀** `.value` 假裝揀好，所以冇事；新 bridge 真係要撳選項 ⇒ 一定要 `dropdownOpen:true`（真機選項係睇得到撳得到，唔係測試遷就實作）。
- `[51]`/`[52]` 保留 `dropdownOpen:false` —— 嗰兩條**刻意**驗「0 個可見選項」要如實報告，仍然有效。

**📌 通用守則（記低，唔好再中）**：
- **要「代按」Element-UI / 任何現代前端元件，一律用真實 pointer 序列，唔好用 `.click()`**。`.click()` 只係 `click` 事件，冇 mousedown、冇座標、冇 `cancelable`；好多 handler 靠 mousedown 開、靠 `cancelable` preventDefault。派完一定要**回讀目標欄位值**做安全網。
- **「開咗但空」≠「冇開」**：判斷展開狀態要用元件自己嘅標記（`is-reverse`/`is-focus`/`aria-expanded`），唔好用「有冇子選項」——選項可能係懶載入／遠端。
- **測試替身要模擬「真實事件入口」，唔止 `.click()`**：`addEventListener` + `dispatchEvent` 缺一，就會出現「產品明明靠事件、測試只測 click」嘅假綠／假紅兩頭唔到岸。
- **修 bridge 之後要問一句**：「有冇舊測試係靠『bridge 唔會真撳』先通過？」（`[2]` 就係），否則修完一個真 bug 會整爆一堆舊測試，令人以為改壞。
